## 用户使用指南

### 1. 系统登录

#### 1.1 获取账号

首次使用需要联系管理员开通账号，您需要提供：
- 工号（Employee ID）
- 联系方式

管理员会为您分配：
- 初始 API Key

#### 1.2 登录系统

1. 访问系统地址：`http://your-domain:8000`
2. 点击右上角"登录"按钮
3. 输入您的工号和 API Key
4. 点击"登录"完成认证

**登录界面示例**:
```
┌─────────────────────────────┐
│      Claude Code 技能注册表  │
│                             │
│  工号: [_______________]     │
│                             │
│  API Key: [_______________]  │
│                             │
│      [ 登录 ]  [ 重置 ]      │
└─────────────────────────────┘
```

#### 1.3 修改 API Key

建议首次登录后修改您的 API Key：

1. 登录后点击右上角用户名
2. 选择"个人设置"
3. 点击"修改 API Key"
4. 输入新 API Key 并确认

> **安全提示**: 请妥善保管您的 API Key，不要与他人分享。

### 3. 上传技能

#### 3.1 准备技能文件

在上传前，请确保您的技能文件包含以下内容：

**必需文件**:
```
your-skill.zip
├── SKILL.md        # 技能元数据（必需）
└── prompt.md       # 技能提示词（必需）
```

**SKILL.md 格式示例**:
```markdown
# Code Review Assistant

一个智能代码审查助手，帮助发现代码中的潜在问题和改进点。

**元数据:**
- **版本**: 1.0.0
- **作者**: 张三
- **类别**: 代码质量
- **标签**: code-review, python, quality

## 功能说明

- 自动检测代码规范问题
- 提供优化建议
- 生成审查报告
```

#### 3.2 上传步骤

1. 登录系统
2. 点击顶部菜单"上传技能"
3. 填写技能信息：

   **上传表单**:
   ```
   ┌───────────────────────────────────────┐
   │ 上传新技能                            │
   ├───────────────────────────────────────┤
   │                                       │
   │ 组织: [ default ▼ ]                   │
   │ 集合: [ default ▼ ]                   │
   │                                       │
   │ 技能文件: [ 选择文件 ]  (最大 50MB)   │
   │                                       │
   │ 版本号: [ 1.0.0 ]                     │
   │                                       │
   │ 描述: [_________________________]     │
   │       [_________________________]     │
   │                                       │
   │          [ 上传 ]  [ 取消 ]           │
   └───────────────────────────────────────┘
   ```

4. 点击"上传"按钮
5. 系统将验证文件格式和内容
6. 上传成功后，技能将进入"待审核"状态

#### 3.3 查看上传状态

1. 点击"我的上传"
2. 查看您上传的所有技能及其状态：

| 技能名称 | 版本 | 上传时间 | 状态 | 操作 |
|---------|------|----------|------|------|
| Code Reviewer | 1.0.0 | 2025-02-09 | ⏳ 待审核 | 详情 |
| Test Helper | 1.2.0 | 2025-02-08 | ✅ 已批准 | 详情 |
| Old Skill | 0.9.0 | 2025-02-01 | ❌ 已拒绝 | 详情 |

#### 3.4 状态说明

- **⏳ 待审核**: 技能已上传，等待管理员审核
- **✅ 已批准**: 技能通过审核，其他用户可见可下载
- **❌ 已拒绝**: 技能未通过审核，需要修改后重新上传

### 5. 使用技能

#### 5.1 安装下载的技能

1. 解压下载的 ZIP 文件
2. 将技能文件放置到 Claude Code 技能目录：

   ```
   ~/.claude/skills/{org}/{collection}/{skill-name}/
   ```

3. 重启 Claude Code

#### 5.2 在 Claude Code 中使用

在 Claude Code 中调用技能：

```
我需要使用 code-reviewer 技能来审查这段代码
```

#### 5.3 技能市场索引

系统自动生成 `marketplace.json` 索引文件，可以被 Claude Code 直接识别和使用。

审核时请注意：
- ✅ 技能描述是否清晰

2. **必须**填写拒绝原因
3. 确认提交

**拒绝原因示例**:
```
❌ 拒绝原因：

请修改以下问题后重新上传：
1. SKILL.md 格式不正确，缺少版本信息
2. 缺少必需的 prompt.md 文件
3. 技能描述过于简单，请补充详细说明
```

### 6. Gitea 集成

#### 6.1 配置 Gitea

在 `.env` 文件中配置 Gitea 连接：

```bash
# Gitea 配置
GITEA_REPO_URL=http://your-gitea:3000/org/repo.git
GITEA_TOKEN=your-gitea-token-here
GITEA_PUSH_INTERVAL=30
```

#### 6.4 手动触发推送

如果需要立即推送：

1. 进入"Gitea 集成"页面
2. 点击"立即推送"按钮
3. 系统将立即处理所有待推送技能

#### 6.5 处理推送失败

如果推送失败：

1. 查看失败原因：
   - Gitea 服务器不可用
   - Token 无效或过期
   - 网络连接问题
   - 文件大小超限

2. 解决方案：
   - 检查 Gitea 服务器状态
   - 更新 Gitea Token
   - 检查网络连接
   - 联系系统管理员

## 常见问题

### 用户常见问题

#### Q1: 忘记 API Key 怎么办？

**A**: 请联系管理员重置您的 API Key。管理员可以：
1. 在用户管理中找到您的账号
2. 点击"编辑"
3. 生成新的 API Key
4. 通过安全方式告知您

#### Q2: 为什么上传的技能一直显示"待审核"？

**A**: 这是正常现象。所有新上传的技能都需要管理员审核后才能发布。审核时间通常在 1-2 个工作日内。您可以：
- 在"我的上传"中查看状态
- 等待审核完成
- 如被拒绝，查看拒绝原因并修改后重新上传

#### Q3: 技能被拒绝了怎么办？

**A**:
1. 查看拒绝原因（在"我的上传"中点击"详情"）
2. 根据拒绝原因修改技能文件
3. 重新上传修改后的技能
4. 等待再次审核

#### Q4: 下载的技能如何安装？

**A**:
1. 解压下载的 ZIP 文件
2. 将技能文件复制到 Claude Code 技能目录：
   ```
   ~/.claude/skills/{org}/{collection}/{skill-name}/
   ```
3. 重启 Claude Code
4. 技能即可使用

#### Q5: 如何查看我的下载历史？

**A**:
1. 登录系统
2. 点击右上角用户名
3. 选择"个人中心"
4. 查看"下载历史"标签

### 管理员常见问题

#### Q1: 如何批量审核技能？

**A**:
1. 进入"待审核"页面
2. 勾选多个技能
3. 选择"批量批准"或"批量拒绝"
4. 确认操作

#### Q2: Gitea 推送一直失败怎么办？

**A**:
1. 检查 Gitea 服务器是否正常运行
2. 验证 Gitea Token 是否有效
3. 检查网络连接
4. 查看系统日志获取详细错误信息
5. 必要时重新配置 Gitea 集成

#### Q3: 如何从 SQLite 迁移到 MySQL？

**A**:
1. 确保 MySQL 服务器已安装并运行
2. 在 `.env` 文件中配置 MySQL 连接参数
3. 使用迁移脚本（如提供）进行数据迁移
4. 验证数据完整性
5. 重启应用

#### Q4: 如何设置定时备份？

**A**:
可以使用 cron 任务（Linux）或任务计划程序（Windows）：

**Linux 示例**:
```bash
# 每天凌晨 2 点备份数据库
0 2 * * * /path/to/backup_script.sh
```

**Windows 示例**:
使用任务计划程序设置定时任务运行备份脚本。

#### Q5: 系统性能如何优化？

**A**:
1. **数据库优化**
   - 定期清理旧数据
   - 添加必要的索引
   - 考虑迁移到 MySQL

2. **存储优化**
   - 定期清理已拒绝的技能文件
   - 归档旧版本的技能
   - 监控磁盘空间

3. **应用优化**
   - 启用缓存
   - 使用 CDN 加速静态资源
   - 优化数据库查询

## 最佳实践

### 对于用户

#### 1. 技能命名规范

使用清晰、描述性的技能名称：
- ✅ 好的命名: `code-review-assistant`, `security-scanner`
- ❌ 不好的命名: `tool1`, `test`, `我的技能`

#### 2. 版本号管理

遵循语义化版本规范：
- 格式: `主版本.次版本.修订版本`
- 示例: `1.0.0`, `1.2.3`, `2.0.0`

#### 3. 编写清晰的描述

在 SKILL.md 中详细描述：
- 技能的功能和用途
- 使用方法和示例
- 依赖和要求
- 已知限制

#### 4. 组织技能文件

保持良好的文件结构：
```
skill-name/
├── SKILL.md          # 必需：技能元数据
├── prompt.md         # 必需：技能提示词
├── README.md         # 可选：详细说明
├── examples/         # 可选：示例文件
└── tests/           # 可选：测试文件
```

#### 5. 测试技能

在上传前充分测试：
- 在本地测试技能功能
- 验证所有文件格式正确
- 检查 SKILL.md 元数据完整
