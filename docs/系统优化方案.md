# Gitea 推送优化和日志系统增强

## 概述

本文档描述了对 Gitea 自动推送逻辑和日志系统的优化方案，包括实施的改进和使用指南。

---

## 一、Gitea 推送优化

### 当前问题分析

| 问题 | 影响 | 优先级 |
|------|------|--------|
| 顺序处理任务，效率低 | 推送延迟高 | 高 |
| 重试策略简单（固定间隔） | 成功率低 | 中 |
| 缺少任务超时控制 | 任务可能hang住 | 高 |
| 缺少并发控制 | 资源竞争 | 中 |
| 错误分类不细致 | 难以诊断问题 | 中 |
| 缺少监控指标 | 运维困难 | 低 |

### 优化方案

#### 1. 并发任务处理

**实现**:
```python
class GiteaPushServiceV2:
    def __init__(self, max_concurrent_tasks: int = 3):
        self.semaphore = asyncio.Semaphore(max_concurrent_tasks)
```

**优势**:
- 多个推送任务并行执行
- 可配置并发数，避免资源耗尽
- 显著提升推送吞吐量

**性能对比**:
```
顺序处理: 3个任务 × 2分钟 = 6分钟
并发处理(3个): 3个任务 × 2分钟 = 2分钟 (提升 3倍)
```

#### 2. 智能重试策略

**实现**:
```python
# 指数退避算法
retry_delay = min(
    self.retry_base_delay * (2 ** attempt),
    self.retry_max_delay
)
```

**重试间隔**:
- 第1次重试: 1秒
- 第2次重试: 2秒
- 第3次重试: 4秒
- 第4次重试: 8秒
- 最大延迟: 300秒 (5分钟)

**优势**:
- 网络抖动时快速恢复
- 避免频繁重试加重负载
- 符合云原生最佳实践

#### 3. 任务超时控制

**实现**:
```python
async def _timeout_monitor(self, task: PushTask, timeout_seconds: int):
    await asyncio.sleep(timeout_seconds)
    # 记录超时并取消任务
```

**配置**:
```python
PushTask(
    id=1,
    ...
    timeout_seconds=600  # 10分钟超时
)
```

**优势**:
- 防止任务永久挂起
- 及时释放资源
- 提高系统可观测性

#### 4. 任务优先级队列

**优先级规则**:
```python
if retry_count > 0 or age > 300:  # 重试过或超过5分钟
    priority = TaskPriority.HIGH
else:
    priority = TaskPriority.NORMAL
```

**排序逻辑**:
1. 优先级高的先执行
2. 同优先级下，创建时间早的先执行

**优势**:
- 重要任务优先处理
- 老任务不会被饿死
- 提升用户体验

#### 5. 错误分类和恢复

**错误类型**:
| 错误类型 | 是否重试 | 处理策略 |
|---------|---------|----------|
| NetworkError | 是 | 指数退避重试 |
| AuthenticationError | 否 | 立即失败，需人工介入 |
| RepositoryNotFoundError | 否 | 立即失败，需检查配置 |
| GitConflictError | 否 | 立即失败，需手动处理 |
| TimeoutError | 否 | 标记为超时，记录日志 |

**优势**:
- 明确的错误分类
- 合理的恢复策略
- 减少无效重试

#### 6. 健康检查和监控

**监控指标**:
```python
metrics = {
    "tasks_processed": 100,      # 已处理任务数
    "tasks_succeeded": 95,       # 成功任务数
    "tasks_failed": 5,           # 失败任务数

    "success_rate": 95.0,        # 成功率 (%)
    "avg_push_time_seconds": 5.26  # 平均推送时间

```

**健康检查输出**:
```json
{
  "timestamp": "2025-02-09T10:30:00Z",
  "level": "INFO",
  "message": "Health check: success_rate=95.0%, processed=100, avg_push_time=5.3s",
  "context": {
    "health_check": true,
```

## 二、日志系统增强

### 当前问题分析

| 问题 | 影响 | 优先级 |
|------|------|--------|
| 日志格式不统一 | 难以解析和分析 | 高 |
| 缺少审计日志 | 不满足合规要求 | 高 |
| 敏感信息泄露风险 | 安全隐患 | 高 |
| 缺少性能追踪 | 难以优化性能 | 中 |
| 日志文件无限增长 | 磁盘空间问题 | 中 |
| 缺少结构化查询 | 问题排查困难 | 中 |

### 优化方案

#### 1. 结构化日志

**格式**: JSON

**示例**:
```json
{
  "timestamp": "2025-02-09T10:30:00.123Z",
  "level": "INFO",
  "logger": "gitea_client",
  "message": "Successfully pushed code-reviewer-1.0.0",
  "request_id": "abc123-def456",
  "context": {
    "task_id": 1,
    "skill_name": "code-reviewer",
    "version": "1.0.0",
    "commit_hash": "a1b2c3d4e5f6...",
    "duration_seconds": 5.26
  }
}
```

**优势**:
- 机器可读，易于解析
- 支持复杂查询
- 与日志分析工具无缝集成

#### 2. 日志轮转和归档

**配置**:
```python
logging.handlers.RotatingFileHandler(
    "application.log",
    maxBytes=10 * 1024 * 1024,  # 10MB
    backupCount=5
)
```

**文件结构**:
```
logs/
├── application.log       # 当前日志
├── application.log.1     # 最新备份
├── application.log.2     # 次新备份
├── application.log.3
├── application.log.4
└── application.log.5     # 最旧备份
```

**归档策略**:
- 单文件最大 10MB
- 保留 5 个备份文件
- 自动删除最旧文件

#### 3. 审计日志

**记录内容**:
- 用户登录/登出
- 技能上传/下载
- 审核操作
- 配置变更
- Gitea 推送

**示例**:
```json
{
  "timestamp": "2025-02-09T10:30:00Z",
  "action": "skill_approve",
  "user": "admin",
  "ip_address": "192.168.1.100",
  "result": "success",
  "details": {
    "skill_id": 456,
    "skill_name": "code-reviewer",
    "version": "1.0.0",
    "comment": "审核通过"
  }
}
```

**优势**:
- 满足合规要求
- 支持安全审计
- 便于问题溯源

#### 4. 敏感信息脱敏

**自动脱敏规则**:
```python
SENSITIVE_PATTERNS = [
    ('api_key', r'(?<=api_key[\'":\s]+)[\w-]+', '***'),
```

**示例**:


#### 6. 请求追踪

**实现**:

**用途**:
- 追踪完整请求链路
- 关联多个日志记录
- 问题排查和调试

## 三、集成和部署

### 1. 安装依赖

```bash
# 无需额外依赖，使用 Python 标准库
pip install -r requirements.txt
```

### 2. 配置日志系统

```python
# main.py
from logging_config import setup_logging

# 初始化日志系统
logger = setup_logging(
    level=os.getenv("LOG_LEVEL", "INFO"),
    log_dir=os.getenv("LOG_DIR", "./logs"),
    enable_json=True,
    enable_console=True
)

# 使用日志记录
logger.info("Skill Registry starting", extra={"version": "1.0.0"})
```

### 3. 启用增强推送服务

```python
# main.py
@app.on_event("startup")
async def startup_event():
    """Initialize database and start background services."""
    init_db()

    # 启动增强的 Gitea 推送服务
    if os.getenv("GITEA_REPO_URL"):
        try:
            from gitea_push_service_v2 import GiteaPushServiceV2

            push_service = GiteaPushServiceV2(
                interval=int(os.getenv("GITEA_PUSH_INTERVAL", "30")),
                max_concurrent_tasks=int(os.getenv("GITEA_MAX_CONCURRENT_TASKS", "3")),
                retry_base_delay=int(os.getenv("GITEA_RETRY_BASE_DELAY", "1")),
                retry_max_delay=int(os.getenv("GITEA_RETRY_MAX_DELAY", "300"))
            )

            asyncio.create_task(push_service.run())
            logger.info("Enhanced Gitea push service started")
        except Exception as e:
            logger.error(f"Failed to start Gitea push service: {e}")
```

## 四、监控和运维

### 1. 日志监控

#### 关键指标

| 指标 | 告警阈值 | 说明 |
|------|---------|------|
| 错误率 | > 5% | ERROR 级别日志占比 |
| 慢操作 | > 1% | 超过阈值的操作占比 |
| 审计失败 | 任何 | 审计日志中的失败操作 |
| 推送失败率 | > 10% | Gitea 推送失败率 |

#### 监控脚本

```bash
#!/bin/bash
# monitor_logs.sh

# 检查错误率
error_count=$(jq 'select(.level == "ERROR")' logs/application.log | wc -l)
total_count=$(jq '.' logs/application.log | wc -l)
error_rate=$(echo "scale=2; $error_count * 100 / $total_count" | bc)

if (( $(echo "$error_rate > 5" | bc -l) )); then
    echo "ALERT: High error rate: $error_rate%"
    # 发送告警
fi

# 检查慢操作
slow_count=$(jq 'select(.context.performance.slow == true)' logs/application.log | wc -l)
if [ $slow_count -gt 10 ]; then
    echo "ALERT: Too many slow operations: $slow_count"
    # 发送告警
fi
```

### 2. 性能分析

#### 使用 jq 分析日志

```bash
# 统计各级别日志数量
jq -r '.level' logs/application.log | sort | uniq -c

# 查找最慢的 10 个操作
jq 'select(.context.performance) | {operation: .context.performance.operation, duration: .context.performance.duration_ms}' \
  logs/application.log \
  | jq -s 'sort_by(.duration) | reverse | .[0:10]'

# 统计推送任务成功率
jq 'select(.context.notification_type == "gitea_push")' logs/application.log | \
  jq -r '.context.status' | sort | uniq -c
```

### 3. 问题排查流程

#### 问题：推送失败率高

1. 检查错误日志
```bash
jq 'select(.context.notification_type == "gitea_push" and .context.status == "failed")' \
  logs/application.log
```

2. 分析失败原因
```bash
jq 'select(.context.notification_type == "gitea_push_failed")' \
  logs/application.log | \
  jq -r '.context.error' | sort | uniq -c
```

3. 检查网络连接
```bash
jq 'select(.message | contains("network"))' logs/application.log
```

#### 问题：性能下降

1. 查找慢操作
```bash
jq 'select(.context.performance.slow == true)' logs/application.log
```

2. 分析数据库查询
```bash
jq 'select(.context.performance.operation == "database_query")' \
  logs/application.log | \
  jq -s 'sort_by(.context.performance.duration_ms) | reverse | .[0:10]'
```

## 五、最佳实践

### 1. 日志记录规范

✅ **推荐做法**:
```python
# 结构化日志
logger.info(
    "技能上传成功",
    extra={
        "skill_name": "code-reviewer",
        "version": "1.0.0",
        "user_id": 123,
        "file_size": 15000
    }
)

# 审计日志
audit_log(
    logger,
    action="skill_approve",
    user_id=1,
    skill_id=456,
    result="approved"
)

# 性能追踪
with PerformanceTracker(logger, "gitea_push"):
    gitea_client.push(skill_zip)
```

❌ **不推荐做法**:
```python
# 所有信息放在消息中
logger.info(f"技能 {skill_name} 版本 {version} 由用户 {user_id} 上传成功")

# 缺少上下文
logger.info("上传成功")

# 不记录异常
logger.error("操作失败")
```

### 2. 推送任务管理

✅ **推荐做法**:
- 合理设置并发数（3-5个）
- 根据网络状况调整超时时间
- 监控推送成功率
- 定期清理历史任务

❌ **不推荐做法**:
- 并发数过高导致资源耗尽
- 超时时间过长导致任务堆积
- 忽略失败任务
- 从不清理数据库

### 3. 监控和告警

✅ **推荐配置**:
- 错误率告警：> 5%
- 慢操作告警：> 1%
- 推送失败告警：> 10%
- 磁盘空间告警：< 20%

❌ **不推荐配置**:
- 告警阈值过高（错过问题）
- 告警阈值过低（误报太多）
- 只监控不告警
- 告警后不处理

## 六、故障案例

### 案例 1: 推送任务堆积

**现象**:
- 待处理任务越来越多
- 已批准的技能未推送到 Gitea

**排查**:
```bash
# 检查任务状态
curl http://localhost:8000/api/admin/gitea-tasks?status=pending

# 检查服务日志
jq 'select(.context.service == "gitea_push_v2")' logs/application.log | tail -20
```

**原因**:
- Gitea 服务器不可用
- 网络连接问题
- 推送服务未启动

**解决方案**:
1. 检查 Gitea 服务器状态
2. 验证网络连接
3. 重启推送服务
4. 调整重试策略

### 案例 2: 日志文件过大

**现象**:
- 磁盘空间不足
- 日志文件达到数 GB

**排查**:
```bash
# 检查日志文件大小
du -sh logs/*

# 统计日志行数
wc -l logs/*.log
```

**原因**:
- 日志级别设置为 DEBUG
- 日志轮转未配置
- 存在循环日志记录

**解决方案**:
1. 调整日志级别为 INFO
2. 配置日志轮转
3. 审计代码减少不必要的日志

### 案例 3: 性能下降

**现象**:
- 推送速度明显变慢
- 平均推送时间 > 10秒

**排查**:
```bash
# 查找慢操作
jq 'select(.context.performance.slow == true)' logs/application.log

# 分析推送时间
jq 'select(.context.performance.operation == "gitea_push")' \
  logs/application.log | \
  jq -s 'map(.context.performance.duration_ms) | add / length'
```

**原因**:
- 网络延迟高
- Gitea 服务器负载高
- 本地磁盘 I/O 慢

**解决方案**:
1. 优化网络连接
2. 增加 Gitea 服务器资源
3. 使用本地缓存
4. 调整并发数
